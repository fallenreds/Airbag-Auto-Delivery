# ТЗ: раскрытие каталога по наведению (десктоп)

## Цель

Пользователь десктопа просматривает дерево категорий в мега-меню каталога
ведением курсора, без обязательного клика по стрелке.

## Область

**Входит**

- Наведение на чип категории с дочерними (`.tp-cat-chip` со стрелкой) раскрывает
  следующий уровень — тот же `.tp-cat-chips-row--sub`, что сейчас появляется по клику.
- Стрелка `.tp-cat-chip__arrow` остаётся видимой и показывает актуальное
  состояние (▾/▴, `aria-expanded`), в том числе при раскрытии наведением.
- Клик по стрелке остаётся рабочим способом раскрыть/свернуть.
- Изменения — в `frontend/src/layout/headers/header-com/menus.jsx`, при
  необходимости стили `.tp-cat-chip*` в `frontend/src/app/globals.scss`.

**Не входит**

- `mobile-menus.jsx`, `mobile-category.jsx` — поведение не меняется.
- Клик по названию категории (`.tp-cat-chip__label`) — по-прежнему навигация на
  страницу категории со сбросом `catalogPath`.
- Другие выпадашки хедера (`user_account`, `sub_menu`) — они на CSS-hover.
- Структура `categoryTree`, `categoryPath()`, API категорий, новые ключи переводов.
- Новые анимации раскрытия, изменение вёрстки рядов подкатегорий.

## Принятые решения

Четыре вопроса, оставленные открытыми на этапе уточнения, закрыты. Основание —
проверка кода и замеры, а не предпочтение.

### Р1. Сворачивание — только при выходе из всего мега-меню

Ряды подкатегорий — **соседние** `<div>` внутри мега-меню, а не вложенные в чип
(`menus.jsx`: root-ряд и `catalogPath.map()` рендерят сёстринские блоки). Чтобы
дойти от чипа до его подкатегорий, курсор обязан пересечь полосу, в которой нет
ни одного интерактивного элемента. По фактическим стилям `globals.scss` она равна:

```
--root padding-bottom   10 px
--root border-bottom     1 px
--root margin-bottom     6 px
--sub  border-top        1 px
--sub  padding-top       8 px
ИТОГО                   26 px
```

Сворачивание по `mouseleave` самого чипа делает ряд подкатегорий недостижимым:
он исчезнет раньше, чем курсор его пересечёт. Поэтому сворачивание остаётся там,
где оно уже реализовано, — `onMouseLeave` на `<li class="has-dropdown has-mega-menu">`.
На уровне чипов работает вытеснение: навёл на соседа — предыдущий свернулся.

Вариант с задержкой 200–300 мс отклонён: он решает ту же задачу ценой таймера и
класса ошибок с зависшими таймаутами, не давая ничего сверх принятого варианта.

### Р2. Триггер — весь чип, не стрелка

Стрелка — 10 px шрифта; попадать в неё курсором неудобно и это противоречит
формулировке «раскрытие просто по наведению». Обработчик вешается на элемент
`.tp-cat-chip` целиком; стрелка остаётся индикатором состояния.

### Р3. Задержки перед раскрытием нет

Ряды добавляются **вниз** и только под уже существующие, поэтому раскрытие
уровня N не сдвигает ряды уровней меньше N. Классической петли
«открыл → сдвиг → mouseleave → закрыл» здесь не возникает ни на одном уровне,
и антидребезговая задержка не нужна. Если на ревью мигание всё же проявится —
добавить 100–150 мс точечно.

### Р4. Клик по стрелке сохраняется

`d-none d-lg-block` скрывает меню только до 992 px, поэтому планшет в ландшафте
(1024 px) рендерит именно этот десктопный компонент и hover не имеет. Без клика
каталог глубже первого уровня стал бы на таких устройствах недоступен. Клик
нужен и для клавиатуры.

## Техническая часть

### Разделение «открыть» и «переключить»

`handleCatalogExpand(cat, levelIndex)` — переключатель: повторный вызов на уже
выбранной категории её сворачивает. Для наведения такая семантика непригодна.
Нужна вторая, идемпотентная операция:

```js
const openCatalogLevel = (cat, levelIndex) => {
  if (!cat.children?.length) return;                 // лист — ничего не меняем
  if (catalogPath[levelIndex]?.id === cat.id) return; // уже открыт — без ре-рендера
  setCatalogPath((prev) => [...prev.slice(0, levelIndex), cat]);
};
```

Клик по стрелке продолжает вызывать `handleCatalogExpand` (переключатель).

### Обработчик — `onMouseEnter` на чипе

Строго `onMouseEnter`, не `onMouseOver`: `mouseover` всплывает и срабатывает
повторно при переходе между `<Link>` и `<button>` внутри чипа. Это же свойство
закрывает сценарий «hover + клик»: после клика, свернувшего уровень, курсор всё
ещё внутри чипа, `mouseenter` заново не сработает, и уровень останется свёрнутым.

Обработчик вешается только на ветку `hasChildren` в `renderCategoryChip`. У чипа-листа
его нет вовсе — это и есть выполнение критерия 5.

### Доступность

`aria-expanded` остаётся привязанным к `isSelected` и поэтому будет меняться при
наведении, без действия пользователя. Это осознанно: рассинхрон между видимым
состоянием и `aria-expanded` хуже. Порядок Tab-обхода, `aria-label`
(`menu.expand` / `menu.collapse` — уже есть в uk/ru/en) и работа Enter/Space не
меняются.

## Критерии приёмки

1. Десктоп (≥ lg), открытое мега-меню, категория первого уровня с подкатегориями.
   Курсор наводится на её чип → без клика появляется `.tp-cat-chips-row--sub` с
   дочерними (отсортированы `sortAlphabetically`), чип получает
   `tp-cat-chip--active`, стрелка ▴, `aria-expanded="true"`.
2. Раскрыта категория уровня N. Курсор наводится на соседний чип того же уровня
   с дочерними → ряд подкатегорий заменяется на дочерние нового чипа, предыдущий
   чип теряет `--active`, уровни глубже N исчезают.
3. Курсор выходит за пределы `<li class="has-dropdown has-mega-menu">` →
   `catalogPath` пуст, все ряды подкатегорий исчезают, все стрелки ▾.
4. Курсор идёт с чипа в ряд его же подкатегорий → ряд не исчезает, подкатегории
   доступны для наведения и клика. «Мёртвой зоны» в 26 px, на которой меню
   сворачивалось бы по дороге, нет.
5. Категория без дочерних. Наведение на её чип → новых рядов не появляется, уже
   открытые уровни выше не сворачиваются, чип остаётся обычной ссылкой.
6. Категория раскрыта наведением. Клик по `.tp-cat-chip__arrow` → уровень
   сворачивается (и наоборот). Страница не перезагружается, навигации нет.
7. Категория раскрыта наведением. Клик по `.tp-cat-chip__label` → переход на
   страницу категории, `catalogPath` сбрасывается.
8. Устройство без hover (`media (hover: none)`). Тап по стрелке → уровень
   раскрывается/сворачивается: каталог управляем без hover.
9. Фокус на `.tp-cat-chip__arrow`, нажат Enter/Space → уровень переключается,
   `aria-expanded` соответствует состоянию, Tab-обход и `aria-label` не сломаны.
10. Оба вхождения `Menus` (обычный хедер, `header.jsx:122`, и sticky,
    `header.jsx:177`) ведут себя одинаково по критериям 1–9. Sticky-контейнер
    уже (`col-xl-7` против `col-xl-8`), чипы переносятся иначе — проверять оба.
11. Мобильная ширина (< lg): `mobile-menus.jsx` и `mobile-category.jsx` не
    изменены, раскрытие там остаётся по клику.

## Краевые случаи

- **Дерево не загружено** (`categoryTree === undefined`, `mounted === false`):
  мега-меню не падает, root-ряд пуст, наводиться не на что.
- **Быстрая проводка курсора через несколько чипов**: не остаётся «зависших»
  уровней, не появляется двух рядов одного уровня одновременно; конечное
  состояние соответствует последнему чипу под курсором.
- **Мигание на границе чипа и ряда подкатегорий**: пока курсор неподвижен,
  состояние не переключается циклически. Обеспечивается ранним выходом
  `openCatalogLevel` на уже открытой категории.
- **Глубокое дерево (3+ уровня)**: каждый новый ряд добавляется под предыдущим.
- **Прокрутка root-ряда колесом** (`max-height: 400px; overflow-y: auto`): чипы
  едут под неподвижным курсором и порождают `mouseenter`. Принято: открытая
  ветка следует за курсором. Требование — не получить пустой `catalogPath` и не
  отрисовать два ряда одного уровня. Если на ревью поведение окажется
  раздражающим, добавить подавление hover на 150 мс после `wheel` в root-ряде.
- **Курсор покидает окно / меню закрывается программно** (переход по ссылке,
  смена маршрута): `catalogPath` сбрасывается, меню открывается свёрнутым.
- **Одновременные hover и клик по одному чипу**: двойного переключения нет —
  см. раздел про `onMouseEnter`.
